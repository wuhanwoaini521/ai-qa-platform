# 实施与验证计划

1. **页面状态与可读性**
   - 固定 trace 展开列约 40px、ID 约 100px；名称占主要空间并可换行；去掉对所有首列生效的 260px 最小宽度。
   - 需求/用例/追踪表使用独立列样式；增加标题完整内容查看和可访问的展开名称。
   - 缩小页面/工具栏/统计卡片的间距。
   - 明确标注“需求状态”“关联用例”“自动化状态”“执行结果”；统一页面、导航、面包屑标题；保持三标签。
   - 显示当前筛选条件、实际结果数和清除入口；统计卡片跳转后结果/筛选一致。

2. **详情、关系与创建**
   - 增加可关闭、键盘可操作的需求详情抽屉，展示描述、真实状态、关联用例、现有来源/更新时间；不展示模型不存在的优先级/负责人/模块，不伪造 Discovery 来源。
   - 抽取并复用生命周期面板现有验收标准文本/结构化 criteria 映射，保存时保留 criterion ID 与 `negative_required`，通过现有 `api.updateRequirement` 更新并同步列表/详情。
   - 需求页真实创建需求，用例页真实创建用例；需求详情内提供关联未关联用例及带项目/需求上下文新建用例。
   - 关联失败保留选择并显示重试；成功更新用例列表、详情和统计；取消创建不调用 API。
   - 执行数据仅按精确的项目/绑定 nodeid/运行/执行映射显示，并附环境、时间和运行详情入口；不满足时明确显示“暂无执行数据”。

3. **自动化测试**
   - 扩展现有 `apps/web/tests/management-model.test.mjs` /新建用户行为测试，验证筛选计数、筛选摘要清除、criteria ID 保留和执行映射边界。
   - 运行相关前端测试、现有 API 需求/用例持久化及 ACL 测试、typecheck、lint、build、i18n 检查。

4. **真实浏览器验收**
   - 独立 API/Vite 端口与 disposable SQLite/workspace，创建合成项目/需求/用例。
   - Playwright 1.62.0 + Chromium，在 1280×800、1440×900、1920×1080 验证全部用户列出的 tabs/filters/cards/details/link/create/cancel/edit/reload/error/empty/keyboard/focus/ARIA 场景。
   - 保存默认列表、详情、关联操作截图；不使用现有 :8000/:5173 服务写入数据，不启动 QA 实际运行。

5. **独立评审与交付**
   - 让 reviewer 与 design director 针对最终差异检查行为、语义、桌面密度和可访问性；修复发现的问题。
   - 更新 `docs/agent-handoff.md` 和本目录执行证据，逐项标注 PASS/BLOCKED/UNKNOWN。
   - 本轮不提交、不推送、不部署。
