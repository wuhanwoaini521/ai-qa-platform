## Defects found and fixed

1. **The pipeline shrank itself to unreadable text.** `WorkflowCanvasPanel` fitted the whole 38-node chain
   whenever the fit zoom was above 0.45 — at 1560 that is 0.47, i.e. ~6 px body text. The floor is now 0.82
   on a host ≥ 900 px (0.72 on a phone), and the chain is panned instead of squeezed. Card fonts went up
   13→14 / 11→12 / 10→11 px so 0.82 still reads.
2. **The execution tree never fitted its host.** The fit effect bailed out silently when the host was not
   mounted or had zero width on the first tick (`if (!host || host.clientWidth === 0) return`), so the tree
   stayed at the default zoom 1 — at 1024 the last column was outside the panel. The effect now retries a
   bounded number of times, reports `maxZoom: 1`, and re-runs when the layout flips.
3. **The tree was unusable on a phone.** A left-to-right tree in a 346 px host is four off-screen columns.
   A host narrower than 720 px now lays the (same) tree out as a vertical list, one card per row, indented
   by depth, with a fixed 300 px card width so a long label cannot push the list off-screen.
4. **A partial trace payload could blank the canvas.** `treeEdges` called `edge.type.toLowerCase()`; a node
   or edge without `type` threw and React unmounted the surface. It now renders as `is-unknown`.
5. **Evidence cards showed a raw enum** (`EvidenceType.ANALYSIS · …`). The label uses the enum's value.

## Honest limits

- The pipeline intentionally does not show all 38 nodes at once on a desktop: legibility wins over fitting,
  and the MiniMap (shrunk to 148×92) plus panning covers the overview. A "fit all" button is not added.
- A synthetic 1000-node trace still lands at 0.7 zoom / 7.7 px text, because the fit is honest about the
  extent. Real traces are 6–33 nodes (definition ≤ 30, project trace ≤ 6 tasks).
- The 100-node stress sample mounted before the panel's 3 s poll replaced it, so its canvas count reads 6;
  the 500 and 1000 samples are the trustworthy ones. Recorded rather than hidden.
- Evidence paging is a server capability with a test; no screen lists raw evidence rows, so nothing in the
  UI pages yet.
- SSE reconnect was verified in Round 16.5 (no duplicate nodes after a reload); this round re-verified the
  "reload re-reads the same ids" half, not an actual socket drop.
