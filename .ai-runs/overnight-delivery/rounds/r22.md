## Defects the acceptance found (and fixed)

1. **The planner could not finish inside its own budget.** `max_tokens=2400` produced
   `workflow_planner FAILED output_limit` after 39.7 s → HTTP 503 for the user. Raised to 6000.
2. **A slow provider exceeded the request timeout.** A 26-node plan took 122 s against a 60 s
   `timeout_seconds` (the request contract caps this at 120) → `FAILED timeout`. Now 120 s, and the
   instruction asks for the shortest workflow (≤ 14 nodes) which brought a real plan to ~50 s.
3. **One malformed reply was fatal.** Added exactly one bounded correction: on a non-JSON reply the same
   request is re-sent once with "Reply with the JSON object only"; a second failure is a 503 with a
   reason. Proven by `test_text_that_is_not_a_plan_is_an_error_not_a_crash` (2 calls) and
   `test_prose_around_the_plan_is_recovered_by_the_single_correction` (1 call).
4. **A declared list input sent as one string invalidated the whole plan** (`INVALID_INPUT: Node
   'run_search_regression' expects 'nodeids' to be list.`). `_inputs` now wraps a non-empty scalar when
   the catalogue declares a list — a shape correction, not a claim.
5. **A scalar where the graph belongs crashed with a 500** (`{"nodes": 3}` → `TypeError`). Guarded;
   `test_a_scalar_where_the_graph_belongs_is_an_error_not_a_500`.

The independent reviewer also flagged two canvas defects, both fixed:

6. **P1 — a live poll reset the pipeline viewport.** The fit effect depended on the `pipelineExtent`
   object, so every 3 s refresh re-ran the fit and pulled a panned user back to stage 1. It now depends
   on `pipelineExtent.right` / `.bottom` primitives.
7. **P2 — the stacked execution tree over-estimated its zoom** because `traceExtent` measured every card
   with the column width (236) instead of the stacked width (300), clipping ~22 px of a deep card.
   Fixed and pinned by `the extent measures a stacked card by its real width`.

## Honest limits

- The P1 viewport reset could not be reproduced end-to-end in this environment: the pipeline projection
  showed only completed records, so no node was ever live and no poll fired during the probe
  (`/tmp/pan-probe.json`: `polls: 0`, viewport held). The fix removes the object identity that caused
  the reset; it is verified by reading, not by a failing-before/passing-after browser run.
- Planner reliability is model-bound: over four consecutive real calls the plan was valid 3 times and
  once returned 503 after a 122 s timeout. The acceptance retries up to 3 times (the UI offers the same
  retry) and reports `attempts`; the final run needed 1.
- The reviewer's P2 about `ExecutionTreePanel`'s `nodesInitialized` dependency is left as is: the effect
  is bounded to one extra fit, and changing it risks the first paint.
- The ACL test for discovery evidence still asserts the admin branch on a non-existent run (the routes
  do inherit `discovery_run_access`; no leak was found). Improving that test is P2 debt.
