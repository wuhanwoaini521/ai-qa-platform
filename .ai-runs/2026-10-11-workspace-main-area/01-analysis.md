# Analysis

- Product journey: requirement → discovery → cases → automation/editor → execution results. Users need the active stage to remain the primary work surface while retaining navigation/context and optional inspection.
- Relevant implementation: `apps/web/src/features/workspace/WorkspacePage.tsx` manages responsive state, context/inspector controls, and grid classes; `workspace.css` defines the shell, grid, mobile stacking and wide-screen Inspector columns. Automation stage already hides context by default; embedded Studio has a separate phone-width file toggle.
- Live Chrome evidence (1524×906): workspace grid 1170px; Cases main is 911px with the context panel, then falls to 519px when Inspector opens (Inspector 380px). Automation main/editor is 1170/872px by default, falling to 778/480px with Inspector. At 1024×768 the 888px grid leaves 629px main with context open. These are the constrained states to fix.
- Root cause: desktop Inspector columns are chosen by viewport media query only; the Workspace itself is much narrower than `window.innerWidth` because application navigation consumes width. The grid also leaves no adaptive context layout between 821px and 1280px, so a visible context rail reduces the main track below a useful width.
- Decision: derive panel modes from the measured Workspace grid width. If a visible context rail would leave less than 820px (960px for code/debug), hide it by default in compact layouts without overwriting the desktop preference; the existing toggle can reopen it, stacked above the main content. When a side-by-side Inspector would leave less than the main minimum (960px for code/debug; 820px for other views), use the existing modal drawer instead. Keep the Inspector side-by-side only when space permits. Preserve the existing ≤820px layout.
- Constraints: do not revert existing user changes, alter domain/workflow behavior, remove context access, or change API/data contracts. Scope is workspace layout only.
- Risk: MEDIUM — responsive UI behavior shared across workspace stages and Inspector focus handling. No persistence or backend change.
- Acceptance: at 1524px, opening Inspector must not shrink Cases main below 820px or code editor main below 960px; at 1024px and 1366px context must not squeeze or shorten the main by default; at 360×640 / 390×844 the main surface uses available height and remains within the viewport, even if the stored desktop context preference is open, while the existing toggle can still reveal context. At wide viewports Inspector may share space only while those minima remain satisfied. Check stage navigation and results/debug-adjacent layout, console and network errors.
