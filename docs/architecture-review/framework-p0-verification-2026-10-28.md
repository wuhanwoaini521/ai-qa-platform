## Research method and interpretation

- GitHub latest-release API metadata provided tag and publication timestamp; each license and manifest was read at the corresponding tag. The pinned README was inspected for deployment/provider/pricing claims. Official docs were read for LangGraph persistence/interrupts, Browser Use quickstart/model directory, and Skyvern deployment paths.
- Vendor documentation and README statements are **documented claims**, not independent project verification. The manifest establishes declared ranges, not successful resolver output or runtime compatibility.
- No candidate was installed or executed. No API calls to a model, cloud browser, or paid provider were made. No local resource measurements, token totals, project-specific cost, recovery evidence, or comparative success rate exists.
- The Skyvern AGPL-3.0 license is recorded as source metadata only. This report does not decide whether a particular SaaS, embedding, distribution, or internal use is compliant; legal review is required before any product dependency or distribution decision.
- Model costs are provider-specific and not inferred from framework documentation. Browser Use's hosted-browser price is a published claim, not a quote or measured total.

## Applicability / decision

The strongest reusable finding is architectural rather than a framework selection: LangGraph documentation explicitly warns that a resumed interrupted node executes earlier code again, reinforcing the need for idempotent effects already present in the target architecture. Browser Use may be a bounded browser-agent benchmark candidate, but its top-level dependency metadata does not settle Playwright 1.62.0 compatibility. Skyvern's service shape, AGPL license and FastAPI range make direct co-installation unattractive without strong evidence and legal review.

**Decision:** KEEP current TaskRuntimeService, BrowserRuntime, DecisionService, provider registry and deterministic Pytest verdict. **DEFER** all three production integrations and the overall Architecture Gate. No candidate was accepted or rejected by benchmark evidence. See the per-framework records in [`engineering-knowledge/frameworks/`](../../engineering-knowledge/frameworks/) and the independent debate in [`architecture-debate-2026-10-28.md`](architecture-debate-2026-10-28.md).
